{# Where the Group by / Split by choices came from. The editor offered the same four names to every backend, two of which Loki answers with nothing and six of which the lab's Elasticsearch index maps and could never be asked for. The list is the SOURCE's now, and this says so — or says why it is the standard four instead, because a cluster that cannot be reached and a source with nothing to group by look identical in a select. #}
{# Panels travel as a JSON blob in one hidden field: the server validates the list as a whole, so posting it as a set of indexed form fields would only mean reassembling it there. #}
Every log panel that counts something is answered by the same request, so adding one costs an aggregation rather than a round trip. A records panel lists rows rather than counting them, which is a search: the board's records panels share one extra request between them. Traces and monitors are other sources: the first panel from each costs one more request, and every further panel from it costs nothing — except a trace list, which asks per service, view and row count. The alert panels read WDash’s own store, so they cost no backend request at all and answer even when the log source does not.
