{# Every third-party asset is pinned to a version and carries a Subresource Integrity hash. A nonce says "this tag is one of ours"; it says nothing about the BYTES the CDN returns, so a compromised or substituted CDN would serve attacker code with a perfectly valid nonce. The hash is what makes that fail closed — the browser refuses content that does not match, and `crossorigin` is required for the check to run at all. Two of these used to be unversioned (`npm/flatpickr`), which means "whatever is latest today" and cannot be hashed by definition. #} {# The mark, twice. The SVG carries its own `prefers-color-scheme` rule, so it is legible on a light tab strip and on a dark one; the PNG is for browsers that do not take SVG here, and it is one colour, measured to hold against both (4.07:1 on white, 3.95:1 on dark chrome). The palette's own cyan is 2.09:1 on white — invisible where half the world reads. #} {# The theme, decided before anything is painted. # # In the HEAD and inline, because the alternative is a page that renders # in one theme and then swaps — which is worse than having no choice at # all, and is exactly what a script at the end of produces. # Inline is allowed here by the nonce; `script-src` carries no # 'unsafe-inline'. # # Stored in the browser rather than on the account. A theme is a # property of the screen somebody is sitting at, not of who they are: # the same operator on a bright wall display and a dark laptop wants two # different answers, and an account-wide setting can only give one. # # `dark` when nothing is stored, which is what every existing # installation already shows. Following the system is a choice somebody # makes, not one made for them by an upgrade. # # `data-theme` drives our palette; `data-bs-theme` drives Bootstrap's # own components. They are set together and never separately — the pair # disagreeing is a page with light dropdowns on a dark background. #}
